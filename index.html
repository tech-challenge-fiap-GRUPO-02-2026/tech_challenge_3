Visão Geral

Do protocolo interno à sugestão auditável

O sistema combina fine-tuning de uma LLM com dados médicos internos (protocolos, FAQs de médicos e modelos de laudo), um pipeline LangChain com RAG sobre esses protocolos e consulta a uma base estruturada de prontuários, e um fluxo de decisão automatizado em LangGraph — tudo isso protegido por guardrails de segurança e logging detalhado de auditoria.

🧬

Fine-tuning (LoRA)

distilgpt2 (padrão, ~90s em CPU) ajustado com peft sobre 71 exemplos curados de protocolos, FAQs, laudos e PubMedQA (traduzido para PT-BR). Pipeline também suporta TinyLlama-1.1B (arquitetura LLaMA real) via --base-model.

🔎

RAG sobre Protocolos

Recuperação por similaridade (TF-IDF local ou FAISS/LangChain) com citação da fonte exata.

🗂️

Prontuário Estruturado

Base SQLite já anonimizada, consultada para contextualizar cada resposta com dados atuais do paciente.

🕸️

Fluxo LangGraph

Exames pendentes → sugestão de conduta → revisão de segurança → alertas para a equipe.

Segurança

Limites de atuação do assistente

🤖 Isto não é um "Claude" ou "ChatGPT" da vida

  • Por padrão, o assistente não é um modelo de linguagem genérico capaz de responder qualquer coisa — ele só consulta a base curada de protocolos internos e FAQs do hospital.
  • Se a pergunta não casar com essa base, ele se recusa a responder em vez de inventar (alucinar) uma conduta clínica plausível-mas-errada.
  • Isso é proposital: num contexto médico é muito mais seguro dizer "não tenho essa informação, procure um médico" do que "chutar" uma resposta sem fonte.
  • Um LLM genérico respondendo livremente sobre condutas médicas, sem citar fonte, é exatamente o tipo de risco que os guardrails deste projeto existem para evitar.

⚠️ O assistente é apoio à decisão — não é o médico

  • Nunca prescreve diretamente — linguagem de ordem médica (ex.: "administre", "injete") é automaticamente reescrita como sugestão.
  • Toda resposta recebe o aviso obrigatório: "requer validação de um médico responsável antes da execução".
  • Perguntas fora do escopo seguro são bloqueadas antes de qualquer geração de resposta.
  • Logging detalhado: cada interação e cada nó do fluxo gera um evento auditável (event_id, timestamp, fontes, flags).
  • Explainability: toda resposta cita o protocolo e a seção exata usados como fonte.
Execução

Como rodar o projeto

Com apenas requirements.txt instalado, todo o projeto roda — RAG, assistente, fluxo clínico e os 26 testes — usando fallbacks leves, sem GPU e sem chave de API.

# 1. instalar dependências mínimas pip install -r requirements.txt # 2. anonimizar prontuários e montar dataset de fine-tuning python -m src.main anonymize python -m src.main build-dataset # 3. perguntar ao assistente (com contexto de paciente) python -m src.main ask "Quando iniciar antibiotico em suspeita de sepse?" --patient-id PAC-0004 # 4. executar o fluxo clínico automatizado (LangGraph) python -m src.main flow --patient-id PAC-0006 # 5. consultar logs de auditoria python -m src.main logs --n 10 # 6. rodar os testes python -m pytest -q # 26 passed
Treinamento em GPU

Fine-tuning de um LLaMA real — NVIDIA ou AMD, sem editar código

O código de treino (src/finetuning/train.py) e o de inferência (src/llm/provider.py) são GPU-aware e agnósticos de fabricante: detectam a GPU via torch.cuda.is_available() — verdadeiro tanto em CUDA/NVIDIA quanto em ROCm/AMD, já que o PyTorch ROCm expõe a mesma API torch.cuda — ativam bf16/fp16 e gradient_checkpointing automaticamente, e caem para CPU sem GPU disponível. O que decide o backend é só qual build do PyTorch é instalada — o mesmo código roda nos dois.

HardwareDriver/stack necessário no sistema
NVIDIADriver NVIDIA (ex.: Fedora → sudo dnf install akmod-nvidia xorg-x11-drv-nvidia-cuda)
AMDStack ROCm/amdgpu — ver rocm.docs.amd.com
🟩

NVIDIA (CUDA)

./scripts/install_torch_nvidia.sh ativa o venv, instala a build CUDA correta do PyTorch e as libs de treino (transformers, peft, datasets, accelerate), e verifica a GPU.

🟥

AMD (ROCm)

./scripts/install_torch_amd.sh faz o mesmo para a build ROCm — mesmo código de treino, sem alterações.

# 1. dependências base (assistente, RAG, fluxo, testes) pip install -r requirements.txt # 2. PyTorch + libs de treino na GPU — escolha o script do seu hardware ./scripts/install_torch_nvidia.sh # NVIDIA (CUDA) # ./scripts/install_torch_amd.sh # AMD (ROCm) # 3. treinar um LLaMA real na GPU (TinyLlama 1.1B — arquitetura LLaMA aberta) python -m src.finetuning.train --base-model TinyLlama/TinyLlama-1.1B-Chat-v1.0 --epochs 3 # 4. avaliar e usar o modelo treinado (auto nunca escolhe o fine-tuned sozinho) python -m src.main evaluate python -m src.main ask "Quando iniciar antibiotico em suspeita de sepse?" --provider local_finetuned

VRAM: o TinyLlama-1.1B cabe em ~6 GB com as otimizações já ativas. Variáveis opcionais permitem trocar a versão do CUDA/ROCm ou o diretório do venv sem editar os scripts (CUDA_CHANNEL=cu124, ROCM_CHANNEL=rocm6.2, VENV_DIR=/outro/venv). Para o Llama 3 oficial da Meta (meta-llama/Llama-3.2-1B), é preciso aceitar a licença no Hugging Face e configurar HF_TOKEN.

Interface de Chat

A forma mais fácil de usar: chat no navegador

Além da CLI, o projeto tem uma interface de chat web completa, com backend próprio feito só com a biblioteca padrão do Python (sem Flask/FastAPI) e front-end estático — tudo sobe com um duplo clique.

🖱️

1. Duplo clique em iniciar_assistente.bat

Confere se o .venv existe, abre o backend numa janela de terminal separada (python -m src.webapp.server, porta 8765) e abre o navegador automaticamente em http://127.0.0.1:8765.

💬

2. Converse com o assistente

Digite a pergunta clínica no chat e receba a resposta com as fontes do protocolo citadas — igual ao comando ask da CLI, só que visual.

🧑‍⚕️

3. Selecione um paciente

Escolha PAC-0001 a PAC-0006 no menu lateral para contextualizar as respostas com o prontuário (idade, diagnóstico, exames, alergias).

⚡

4. Perguntas rápidas + fluxo automatizado

Chips na lateral disparam perguntas já validadas — inclusive uma marcada com ⚠️ que demonstra o bloqueio dos guardrails ao vivo. O botão "Rodar fluxo automatizado" executa o LangGraph completo para o paciente selecionado, direto no chat.
